# 真正踩过的坑，以及高效修正

以下来自长离和秧秧工程中的用户反馈与工程记录。它们说明问题与修复方法，不表示所有细节已经得到最终美术验收。秧秧的制作顺序、具体修复记录与未验证范围见 [案例](yangyang-case-study.md)。

## 1. “是红头发，但不是长离”

错误：用笼统的 Q 版红发角色替代指定角色，或者把参考风格理解成颜色相似。

修正：回到用户原图，逐项核对发束轮廓、眼睛花纹、双侧饰品、服装与小凤凰。先稳定辨识度，再增加动作。参考作者的弹性与节奏，不复制其角色资产。

经验：漂亮的泛用角色不能满足具体角色需求。画得更多也不能弥补认不出来。

## 2. 头发越补越多，脸也歪了

错误：每次补局部都扩展轮廓，左右脸与头发同时改变，最后失去原图结构。

修正：保持相同尺度和基准点对齐参考；检查脸轮廓、眼睛中线和饰品位置。明确哪些不对称来自原图的倾斜，哪些是新造成的失衡。每次只修一个边界。

经验：不能把“更蓬松”当作美化标准，也不能把所有天然不对称强行改成镜像。

## 3. 手一挪开，脸、鼠标和尾羽就缺角

错误：只把覆盖区域抠掉，没有补全被遮挡物体；靠镂空让手与身体不重叠。

修正：先补完整鼠标与脸/衣服 underpaint，再用层级让手在上面。缺少尾羽的外轮廓必须在源图或明确的修复层补齐，而不是无限扩大已有残片。

经验：遮挡关系需要完整对象。不能用删除底层像素替代正确排序。

## 4. 补脸是一块平色贴纸

错误：色块的颜色近似皮肤，但亮暗、纹理和描边接不上；转头时补片还滞留原位。

修正：优先采样原模型真实皮肤区域，羽化内部接缝、保留外轮廓；把补片绑定到原生网格/UV 三角形，随当前头部形变更新。

经验：中性截图接得上不代表运动中接得上。检查反方向转头和手部极值。

## 5. 鼠标只按一只手，键盘却把双手都按下

错误：按动作名直觉分配左右手，或者 BothPress/旧 motion 没被清掉。

修正：先写所有输入的手部归属表；查真实参数和导出 motion，释放暂态残留但保留真实按住状态。键盘、鼠标通道分离；松开后重新按下可以重触发，系统autorepeat不重启按压或头部弹簧。

经验：KeyboardLeft/Right 可以表示键盘区域，也可能是导出动作名称，不能直接解释成角色左/右手。

## 6. 明明分四区，实际上还是每次敲空格

错误：只有按压，没有二维落点；键盘朝向与手移动的坐标定义相反。

修正：在参考图上标出真实前后与左右。单手模式由同一手覆盖，双手模式按用户要求分区；伸手分别控制横向与深度，Space单独落点。区域规则覆盖完整键盘，不只写Q/A/U/H。

经验：先证明手确实落到四处，再扩大动作幅度。透视与坐标错误不能靠更强弹性解决。

## 7. 胸口把移动的键盘手吞掉了

错误：中性手位置没被挡，因此没检查 draw order；伸手后手进入身体下层。

修正：把明确指定的手层放到胸/衣服锚点之后，保留其余 drawable 的相对顺序和遮罩。检查所有 reach/depth 极值。

经验：不要整体抬高几十个图层，只调整需要变化的局部排序。

## 8. 鼠标没动，只有手在滑

错误：输入只驱动手部偏移，鼠标贴图与线缆仍在静态背景里。

修正：将鼠标完整拆出，与手/线缆共享位移源；手指按压与整组平移分离。保持鼠标下面有完整底图。

经验：交互对象要一同移动，不能只动身体的一部分。

## 9. 斗鸡眼、眨眼生硬、开心却闭眼

错误：两眼 gaze 符号/范围不一致，blink 和 expression 相互覆盖，或者 Smile 导出资产被错误地当成通用开心。

修正：使用共同目标核对参数方向，降低不自然的极值；闭合、保持、睁开分阶段插值，表情控制基础眼睛开放程度。困倦明确闭眼，开心使用用户认可的笑眼/开放度。离开表情时释放旧状态。

经验：表情名称不是画面。每个用户能选的按钮都要对应可见、不同的实际状态。

## 10. 右键菜单挡住主体，拖一下还消失

错误：菜单固定叠在角色上方；窗口移动引发失焦，失焦回调立即隐藏它。

修正：以角色可见 bounds 计算旁边可用空间。菜单采用独立浮动窗口，明确关闭、Esc 和动作选择的收起时机；不要在系统拖动过程中用 blur 自动关闭。

经验：浏览器拖动正常不能证明原生窗口的焦点生命周期正常。

## 11. 已经启动了，必须再点桌面才活过来

错误：全局监听/活动状态被初始化时的焦点或窗口过滤挡住，没有在模型 ready 后正确衔接。

修正：把 hooks 初始化与角色 ready 状态分开，检查启动握手及前台过滤条件；冷启动后不点击桌面，直接键盘/鼠标测试。

经验：热更新或已经激活过的开发窗口不是冷启动证据。

## 12. 缩放了主体，按键和气泡像贴在屏幕上

错误：主体使用百分比，覆盖层仍使用固定像素；native window 尺寸没有跟随。

修正：让主体和覆盖层使用同一缩放容器，动态调整原生窗口边界；对连续滑条做合并与最终提交，确认 50/100/200% 的可见比例。

经验：缩放不仅是 CSS transform；窗口、交互区域、布局、字体和持久化都有关。

## 13. 代码/Core 通过了，就说原生已经交付

错误：把文件检查、单元测试或 Core 参数验证当作真实 WebGL 与 Windows 能力验收。

修正：分开记录文件、Core、浏览器和原生证据；不能操作原生时如实列为待验收。用户实测另外记录来源。

经验：测试数量不是交付质量，更不能掩盖没看过实际画面。

## 14. 不断检查，却没有保存；版本还互相覆盖

错误：把进度留在对话或编辑器内；长时间构建前没有检查点；新 EXE 覆盖旧 EXE。

修正：每个里程碑立即保存代码/模型/证据/下一步，独立版本目录与 SHA，常规提交记录。检查已经证明的事情不重复跑，遇到新改变再扩大验证。

经验：能继续工作的持久化状态比“我会记得”可靠。

## 15. 工具权限卡住后，一直要求用户重新同意

错误：把网络/文件权限、应用操作权限和 SDK 许可混为一谈；认为再次文字确认就能修复工具拒绝。

修正：引用实际工具错误，检查工具是否能看到 Java/Cubism 窗口和真实应用能力。保留已有授权，继续不依赖被拒工具的工作；不要虚报绑定已经完成。

经验：权限问题要定位到具体工具和操作，不能把所有阻碍都归为“没给完全访问”。

## 16. “更Q一点”却看不出变化

错误：在未认可的插画范式里只增大眼睛、增加可爱标签。修正：重新分配头/身体/手/键鼠体量，减少场景和复杂衣纹；认可后转入局部修补。不能将探索期的大改方法用于用户已锁定的底稿。

## 17. 新角色被画成长离，或每轮眉心纹样都变

错误：混用身份参考与构图参考，或者把玄翎案例的具体瞳色/纹样作为全角色默认。修正：身份卡、构图卡、编辑契约分开；不确认的官方细节标明待核，按用户指定局部参考修补。

## 18. 关掉长按浮显，桌宠还是抖

错误：只抑制提示DOM，pressedAt、spring kick和动作机仍处理每次OS重复。修正：down/repeat/up分流，当前按住集合维持手姿，重复不重新触发，up后同手有键则继续保持。提示重复开关与动作完全分离。

## 19. 发布前测过开关，用户却找不到按键提示

错误：测试中途失败，恢复了一个已经被前一测试误改的基线。修正：测试前保存偏好，使用finally恢复，核对本次用户最新要求、持久化值和运行窗口状态。不能只断言源码默认true。实际长离中出现过误关，已恢复，这也是要写进流程的错误。

## 20. 游戏设置能读键，实际操作角色不行

错误：只验证登录/设置界面，或反复加监听却不查权限。修正：帧与输入计数分开，确认前台完整性差异，再用用户授权的标准管理员模式核验真实玩法。Raw Input注册不等于事件持续；GetAsyncKeyState低位不是可靠按下记录。

## 21. 有了Mac安装包，就沿用旧版的Mac实测结论

错误：ZIP CRC、ARM64和版本正确就称“新版本Mac已验收”。修正：逐字节保留上游附件，记录精确来源；文件检查与本版目标OS运行分开。源码分支可能早已通过PR合并，push失败先fetch看祖先关系，不强推。

## 22. 已上传了，却因为网络超时重新发布一份

错误：把元数据超时当文件上传失败，覆盖附件或创建重复Release。修正：先查同名草稿和资产ID/大小/哈希，只续传缺失项。对只读元数据可有界重试；创建/发布结果不明时先重新查询，不能盲重试写操作。

## 23. 同一张底稿越修越窄、越鲜艳

错误：局部问题用全图重绘、非等比缩放或全局滤镜解决。修正：固定认可底稿，先查显示变换/色彩配置，再用原像素裁层和隐藏区补绘；保护区做同尺度差分。瞳色只改指定虹膜，不来回调整全图。见 [分层与绑定](layering-rigging.md)。

## 24. 手和眼都拆出来了，动起来仍带着脸和头发

错误：移动粗矩形裁片，底图同时保留旧眼/旧手残像。修正：两眼、两手分别隔离检查，掌部/末端袖口/后袖分工；补齐被遮挡的对象，虹膜使用本眼开口遮罩。不能修完一边就宣布另一边也好。见 [眼部与表情](eye-and-expression.md)。

## 25. 困倦像开心，脸红只是粉红椭圆

错误：按情绪名贴符号，没有眼睑、嘴形和脸部结构变化；闭眼时保留睁眼轮廓。修正：先解决完整闭合，再分辨情绪；隐藏辅助符号看脸是否成立。脸红沿脸型晕染并跟随变形，进入/保持/退出均检查。见 [审美指南](aesthetic-guide.md)。

## 26. 窗口是透明的，却挡住后面软件的点击

错误：用矩形窗口或 CSS pointer-events 代替原生命中；穿透后又依赖网页收到鼠标事件恢复。修正：可见 Alpha 加真实工具热点，原生独立检测，内部孔洞和底边留白通过；拖动时固定点击归属。命中数据更新与物理点击成功分别取证。见 [窗口与设置](windows-settings.md)。

## 27. 鼠标没动，眼睛却永远不回正

错误：相同的轮询数据不断刷新空闲计时，或移动检测只看已钳制的目标。修正：记录真实移动；视线延迟/回正与鼠标手分开，范围外移动仍可被识别，重新移动及时接回。不要每次收到 native sample 就重启计时。见 [动作架构](runtime-native.md)。

## 28. 静态版只是关了开关，便携 EXE 也启动不出画面

错误：共用动态入口和整套资源，原生仍监听键盘；或把开发 URL/错误 frontendDist 带进独立包。修正：独立入口/资源/能力限制，检查实际加载和监听状态；停开发服务器后启动真正 EXE。安装器、便携文件、静态与互动版分别核验并给准确入口。见 [验收与交付](release-validation.md)。
