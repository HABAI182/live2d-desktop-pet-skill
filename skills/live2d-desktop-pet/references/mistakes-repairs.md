# 真正踩过的坑，以及高效修正

以下来自长离工程中的用户反馈与工程记录。它们说明问题与修复方法，不表示所有细节已经得到最终美术验收。

## 1. “是红头发，但不是长离”

错误：用笼统的 Q 版红发角色替代指定角色，或者把参考风格理解成颜色相似。

修正：回到用户原图，逐项核对发束轮廓、眼睛花纹、双侧饰品、服装与小凤凰。先稳定辨识度，再增加动作。参考作者的弹性与节奏，不复制其角色资产。

经验：漂亮的泛用角色不能满足具体角色需求。画得更多也不能弥补认不出来。

## 2. 头发越补越多，脸也歪了

错误：每次补局部都扩展轮廓，左右脸与头发同时改变，最后失去原图结构。

修正：保持相同尺度和基准点对齐参考；检查脸轮廓、眼睛中线和饰品位置。明确哪些不对称来自原图的倾斜，哪些是新造成的失衡。每次只修一个边界。

经验：不能把“更蓬松”当作美化标准，也不能把所有天然不对称强行改成镜像。

## 3. 手一挪开，脸、鼠标和尾羽就缺角

错误：只把覆盖区域抠掉，没有补全被遮挡物体；靠镂空让手与身体不重叠。

修正：先补完整鼠标与脸/衣服 underpaint，再用层级让手在上面。缺少尾羽的外轮廓必须在源图或明确的修复层补齐，而不是无限扩大已有残片。

经验：遮挡关系需要完整对象。不能用删除底层像素替代正确排序。

## 4. 补脸是一块平色贴纸

错误：色块的颜色近似皮肤，但亮暗、纹理和描边接不上；转头时补片还滞留原位。

修正：优先采样原模型真实皮肤区域，羽化内部接缝、保留外轮廓；把补片绑定到原生网格/UV 三角形，随当前头部形变更新。

经验：中性截图接得上不代表运动中接得上。检查反方向转头和手部极值。

## 5. 鼠标只按一只手，键盘却把双手都按下

错误：按动作名直觉分配左右手，或者 BothPress/旧 motion 没被清掉。

修正：先写所有输入的手部归属表；查真实参数和导出 motion，逐帧释放按压残留。键盘、鼠标通道分离；重复按同键也根据时间重新触发。

经验：KeyboardLeft/Right 可以表示键盘区域，也可能是导出动作名称，不能直接解释成角色左/右手。

## 6. 明明分四区，实际上还是每次敲空格

错误：只有按压，没有二维落点；键盘朝向与手移动的坐标定义相反。

修正：在参考图上标出真实前后与左右。普通键归同一键盘手，伸手参数分别控制横向与深度；Space 单独落点。区域规则覆盖完整键盘，不只写 Q/A/U/H 四个示例。

经验：先证明手确实落到四处，再扩大动作幅度。透视与坐标错误不能靠更强弹性解决。

## 7. 胸口把移动的键盘手吞掉了

错误：中性手位置没被挡，因此没检查 draw order；伸手后手进入身体下层。

修正：把明确指定的手层放到胸/衣服锚点之后，保留其余 drawable 的相对顺序和遮罩。检查所有 reach/depth 极值。

经验：不要整体抬高几十个图层，只调整需要变化的局部排序。

## 8. 鼠标没动，只有手在滑

错误：输入只驱动手部偏移，鼠标贴图与线缆仍在静态背景里。

修正：将鼠标完整拆出，与手/线缆共享位移源；手指按压与整组平移分离。保持鼠标下面有完整底图。

经验：交互对象要一同移动，不能只动身体的一部分。

## 9. 斗鸡眼、眨眼生硬、开心却闭眼

错误：两眼 gaze 符号/范围不一致，blink 和 expression 相互覆盖，或者 Smile 导出资产被错误地当成通用开心。

修正：使用共同目标核对参数方向，降低不自然的极值；闭合、保持、睁开分阶段插值，表情控制基础眼睛开放程度。困倦明确闭眼，开心使用用户认可的笑眼/开放度。离开表情时释放旧状态。

经验：表情名称不是画面。每个用户能选的按钮都要对应可见、不同的实际状态。

## 10. 右键菜单挡住主体，拖一下还消失

错误：菜单固定叠在角色上方；窗口移动引发失焦，失焦回调立即隐藏它。

修正：以角色可见 bounds 计算旁边可用空间。菜单采用独立浮动窗口，明确关闭、Esc 和动作选择的收起时机；不要在系统拖动过程中用 blur 自动关闭。

经验：浏览器拖动正常不能证明原生窗口的焦点生命周期正常。

## 11. 已经启动了，必须再点桌面才活过来

错误：全局监听/活动状态被初始化时的焦点或窗口过滤挡住，没有在模型 ready 后正确衔接。

修正：把 hooks 初始化与角色 ready 状态分开，检查启动握手及前台过滤条件；冷启动后不点击桌面，直接键盘/鼠标测试。

经验：热更新或已经激活过的开发窗口不是冷启动证据。

## 12. 缩放了主体，按键和气泡像贴在屏幕上

错误：主体使用百分比，覆盖层仍使用固定像素；native window 尺寸没有跟随。

修正：让主体和覆盖层使用同一缩放容器，动态调整原生窗口边界；对连续滑条做合并与最终提交，确认 50/100/200% 的可见比例。

经验：缩放不仅是 CSS transform；窗口、交互区域、布局、字体和持久化都有关。

## 13. 代码/Core 通过了，就说原生已经交付

错误：把文件检查、单元测试或 Core 参数验证当作真实 WebGL 与 Windows 能力验收。

修正：分开记录文件、Core、浏览器和原生证据；不能操作原生时如实列为待验收。用户实测另外记录来源。

经验：测试数量不是交付质量，更不能掩盖没看过实际画面。

## 14. 不断检查，却没有保存；版本还互相覆盖

错误：把进度留在对话或编辑器内；长时间构建前没有检查点；新 EXE 覆盖旧 EXE。

修正：每个里程碑立即保存代码/模型/证据/下一步，独立版本目录与 SHA，常规提交记录。检查已经证明的事情不重复跑，遇到新改变再扩大验证。

经验：能继续工作的持久化状态比“我会记得”可靠。

## 15. 工具权限卡住后，一直要求用户重新同意

错误：把网络/文件权限、应用操作权限和 SDK 许可混为一谈；认为再次文字确认就能修复工具拒绝。

修正：引用实际工具错误，检查工具是否能看到 Java/Cubism 窗口和真实应用能力。保留已有授权，继续不依赖被拒工具的工作；不要虚报绑定已经完成。

经验：权限问题要定位到具体工具和操作，不能把所有阻碍都归为“没给完全访问”。
