# 底稿生成与局部修图

## 先判断探索还是修补

没有认可底稿，用户还说“不够 Q”“像插画”“感觉没变”时，应改变头身结构、身体露出量、键鼠比例和画面密度。只在原风格上增加可爱形容词，通常不会改变结果。

用户认可主体后再说“只改这里”，则沿用那张图做局部编辑。不要因修键盘重新设计脸、眼睛、刘海、配色或配角。认可的是视觉方向，不代表每个细节和键盘几何都正确。

已有程序任务不需要重新生图。素材、绑定与渲染问题先分清，再选择修改资产或代码。

## 三张卡，而不是一串形容词

| 卡片 | 内容 | 边界 |
| --- | --- | --- |
| 身份卡 | 角色、用户设定、可核实的发型/瞳色/饰品/服饰/纹样 | 默认参考角色资料；用户明确的二创改变优先 |
| 构图卡 | 头身体量、镜头、键鼠、手、配角、背景、留白 | 参考布局与节奏，不复制他人模型或贴图 |
| 编辑契约 | 当前底图、允许改的区域、保护区、接缝和验收点 | 只对本轮局部任务冻结，不阻止已授权的工程推进 |

资料不足时不要按案例补成另一个角色。用户自设按自设；要核对真实设定时用清晰来源，无法读取的图或页面标为未核实。

## 从零起稿：先搭适合动的画面

1. 用常用桌面小尺寸判断轮廓：大头为主、小段躯干、小而短的手，角色与输入设备有明确接触。Q 感来自体量关系，不只是大眼睛。
2. 为眼睛、嘴、手、发束和饰品留运动空间。压在脸上的袖口、过密耳饰、遮满手的键盘都会增加补绘和绑定成本。
3. 线条、阴影保持可分层与可辨识。减少没有动作用途的碎花和高光。配角的体量/对比度低于主角。
4. 键盘按 [空间规则](keyboard-space.md) 确定。无线/有线、配角、键位配列属于当前项目，不照搬样张中的相反要求。
5. 优先少量差异明确的候选，指出改变的是头身关系、姿态还是线条语言，避免多张肉眼几乎相同的重抽。
6. 方向确认后存档，再精修和分层。持续自主推进已获授权时，可保存最符合明确标准的候选继续工程，标明视觉确认状态，不重复索取同一确认。

## 局部修补：缩小改动，保护底图

使用能读取当前底图的图像编辑工具，先读其实际说明；不要假装拥有遮罩、种子锁定或分层输出。已有矢量键盘与代码图形优先直接编辑几何源。

编辑输入包括底图、相关身份参考、可改区域及必要缓冲、保护区、目标形体和失败判据。每张参考注明职责，无关角色图不混入身份条件。

| 问题 | 合适范围 | 防回归 |
| --- | --- | --- |
| 键盘方向/空格错误 | 键盘和必要接触阴影；可用几何键盘作透视锚 | 脸、手长、鼠标和配角被重画 |
| 两眼看向不同点 | 虹膜/瞳孔中心和必要眼睑过渡 | 改头角度补偿眼神，眼形被放大或变方 |
| 额头纹样错误 | 纹样及实际遮住它的极小发丝范围 | 长出大刘海，把案例约束当普遍官方设定 |
| 袖子过密 | 袖面装饰与接缝，保留大色块和形制 | 拉长手臂，更换袖口与接触姿势 |
| 发量/脸型漂移 | 指定外轮廓和补片边界 | 整头变大，将自然歪头强行对称 |

锁区不是口头承诺。不能保证像素不变时，交付前比较未改区域；明显漂移则退回基准图改方法，不声称“其他完全没动”。

## 反复失败时换方法

第二次仍有相同结构性错误，就检查参考和坐标假设，改用局部编辑、几何锚或可编辑源，不再重复一句“correct keyboard”。这是节省尝试的经验点，不是必须耗完两轮才能换方法。

合成或手工绘制需有合适工具并在用户范围内，统一光向、描边、阴影与透视。确定性生成键帽几何不等于完成角色重绘。

## 静态验收门

先核对本轮要求，再看身份、脸和手结构、键鼠方向、配角、轮廓和保护区回归。美术评分不能掩盖错角色或重复空格。

白底样张是构图稿，不因此成为透明分层、可动 PSD 或正式 Live2D。后续仍需遮挡补全、拆层、绑定和导出；程序可用标注清楚的占位图同步推进。
