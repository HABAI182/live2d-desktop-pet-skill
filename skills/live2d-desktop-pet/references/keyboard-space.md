# 键盘方向、真实配列与动作落点

## 先选观察方向

“角色坐在键盘后方，面朝观众”时，角色是打字者，观众在键盘对面。**靠打字者的空格行在画面上侧，数字行较靠画面下侧；实体左区投影到画面右侧。** 背对观众或同向俯视时规则随视角改变，不能强套。

修复前同时记录物理左右、打字者近远、屏幕左右上下、角色左右手和模型网格名称。只翻上下行、不处理左右映射，会制造另一种镜像错误。

```text
                    角色 / 打字者
                   空格与修饰键行
                      Z…M 行
                      A…L 行
                      Q…P 行
                      数字行
                       观众
  屏幕左侧 = 实体右区          屏幕右侧 = 实体左区
```

## 不用随机方块代替真实配列

先选配列，再确定可省略细节。紧凑 60% 是方便的示例，不是强制。标准示例只有一根约 6.25u 空格；Enter、Shift、Tab、Backspace 按真实相对长度保留。其他配列按实际尺寸，不把 6.25u 套给所有键盘。

不用密集刻字堆真实感。键帽比例、错位行列、单根空格、薄厚与统一透视更重要；可以弱化刻字，不能掩盖几何错误。

```sh
python scripts/keyboard_layout.py --view front-facing-pet --output-dir /path/to/new-reference
```

脚本路径以 skill 目录为基准。输出自绘 SVG 与 JSON，不修改角色原图或工程，不覆盖已有输出。`typing-view` 用于普通同向打字视角。

## 分区覆盖完整键盘，不是四个示例键

Q/A/U/H 可说明四区，不能就是实现支持的全部键。应用映射还应考虑数字、标点、功能区、修饰键、方向键和小键盘；平台键码、修饰键合并和 fallback 要明确。

常见物理划分：Q–T/A–G/Z–B 为左区，Y–P/H–L/N–M 为右区；数字和标点按布局延伸。前后边界按模型定义，Space 单独落点。允许不同输入布局重映射，不按输入文字猜物理位置。

错位键列的边界不等于一根50%竖线：例如Y/H的几何中心可能落在全键盘中线左边，但仍属于此示例的右键区。几何坐标与逻辑区域要分别保存，不能仅按x小于0.5决定所有键。

脚本仅为自身 60% 布局的每个键给出物理/屏幕坐标和区名，不宣称覆盖全尺寸键盘或提供完整 OS 键码表。应用要补齐其它键区与平台码。

## 手部归属由需求决定

- 单手键盘：全键盘交给指定手，在四区移动；另一手专管鼠标。
- 双手键盘：实体左右区分别交给角色左右手；鼠标手在键盘忙时由键盘优先，空闲后回鼠标。
- 网格 Left/Right 可能按画面命名，不直接对应解剖侧。用物理输入和可见手确认。

按压、横向、前后伸手分别控制。先对落点，再扩大幅度；前后透视位移通常更克制。扩大前确认底图、袖口衔接与手在胸前的排序。

四个物理区各选一键，补 Space、快速跨区、同手多键、键盘→鼠标。观察对应的手与投影落点，不只核对事件名。几何正确仍不等于原生键码与参数符号正确。
