# 秧秧玄翎：单图制作、反复纠错与交付

这是截至 2026-10-19 的方法复盘，来自用户反馈、当前工程入口和本地验收记录。公开技能只收录经过整理的方法，不附原画、PSD、CMO3、运行模型、聊天原文或私人账号操作记录。案例采用的修法不表示所有历史问题都取得最终人工认可。

## 起点与最后保留的方向

输入只有一张已认可的平面底稿，没有分层 PSD 或 Cubism 模型。用户要求保留比例、配色与大头构图；选择原图像素抠图拆层，仅补绘遮挡区。头发局部缺角允许极小修补/减量，不允许连带重画其他部位。

这是本项目的修复约束，不代表后续合成底稿与最初附件逐字节相同。每轮基准必须指向实际采用的认可版本，不能用同构图副本的哈希冒称原始附件哈希。

本例中，角色左手（画面右侧）操作键盘四区和独立 Space，角色右手（画面左侧）与鼠标一起滑动。灰蓝瞳、蓝黑到蓝白发梢、额纹、羽饰金花红穗与玄翎雀是本项目的辨识点。新角色不能继承这些身份细节或手部默认。

## 制作顺序及转向原因

| 阶段 | 做法与调整 | 应留下的检查点 |
| --- | --- | --- |
| 接手 | 定位实际入口、认可底图、原生程序和未完成项 | 底图版本、手部归属、当前源码/模型来源 |
| 原画拆层 | 放弃会使整体变窄、增艳的反复重绘，保留可见原像素 | 同尺寸叠图、保护区差分、隐藏区补绘范围 |
| 补全与绑定 | 先补脸、头发、衣服和鼠标底层，再拆眼、手袖与配角；保存真实 CMO3 并导出 | 可编辑源与导出包成对，图层/参数/遮罩 ID |
| 结构纠错 | 在中性和动作极值检查白边、缺角、双眼残框及手袖夹带 | 同一坏姿态的修前/修后对照 |
| 动作和情绪 | 独立键鼠、四区与 Space、受控弹性、鸟的次级运动、视线与空闲回正 | 输入状态、实际画面、情绪切换与回正记录 |
| 桌面体验 | 对齐气泡/按键、统一视觉语言、收紧菜单、透明轮廓命中 | 实际原生窗口的布局、点击与恢复入口 |
| 分版交付 | 最终保留静态、基础互动、表情完整三个用途；取消的 VTS/工程商品不延续 | 每版功能矩阵、独立配置、真实 EXE 与校验值 |

修复期间可继续程序和文档工作；编辑器阻塞不应让整个工程停下。长任务断开或额度恢复时，先读检查点与最新发行索引，再接实际未完成步骤。

## 反馈怎样转成可操作问题

表中“修法”包含实际采用的方法和以后应采用的验收要求；不要把这张表当成全部已通过清单。

| 用户观察 | 失败原因或应核查的假设 | 修法与验收重点 |
| --- | --- | --- |
| 变窄、过饱和 | 裁图或显示非等比；重绘/色彩处理漂移 | 同画布等比叠图，检查显示变换与色彩配置；保护区做差分 |
| 瞳色先太蓝又太青 | 无固定参照，来回凭感觉改色 | 固定身份参考，只改指定虹膜，连同肤色/发色作防回归 |
| 发饰和发环有白边 | 背景混色、真高光、遮罩露色或混合设置可能混淆 | 黑/白/灰/棋盘格定位机制，局部修边，不全图腐蚀 |
| 左侧头发缺角 | 源裁片/画布裁切/网格或动作越界 | 先找损失层级；只补极小缺口或已许可的少量修剪 |
| 两手带脸、头发、长袖残片 | 把粗矩形当作独立手层；底层没补齐 | 掌部、末端袖口和后袖分工；先补根部，检查四区和鼠标 XY 极值 |
| 两眼抠像始终不对 | 旧眼、眼白、虹膜、睫毛与补片多重叠加 | 逐层隔离；每眼单独修；检查原生遮罩、运行时跟随和底图残像 |
| 困倦闭眼后仍诡异 | 旧睁眼框残留；后续又把笑眼当困眼 | 结构闭合与情绪语义分两轮修；去掉 Zzz 仍应看得出困意 |
| 脸红只是两个粉椭圆 | 装饰代替脸部表演 | 沿脸部曲面晕染，配合嘴/眼/姿态，检查跟随头部变形 |
| 弹性弱、鸟不活泼 | 单一平移，主次同相位或输入被重复重置 | 输入压下/保持/回弹分开，头发饰物滞后，鸟有独立根部与余韵 |
| 鼠标手幅度小 | 映射幅度偏小；只改手未改鼠标会穿帮 | 同驱动扩大整组位移，袖根渐变衔接，联查其他手和眼睛 |
| 盯鼠标太呆 | 视线一直保持目标，缺少空闲语义 | 可调延迟后平滑回正，真实移动恢复；不改变鼠标手目标 |
| 文字泡位置高、键提示小 | 把口头位置描述误当最终需求；尺度分离 | 以用户更正为准：本例移动文字泡下移并略左，保留键提示原高度 |
| 右键菜单下方大片空白 | DOM 内容缩短而原生窗仍用固定高度 | 内容变化后同步原生窗口；折叠/展开、字号变化都检查 |
| 透明处和桌宠下面点不到 | 窗口透明但命中仍是整块矩形 | Alpha 轮廓及内部孔洞/底部留白穿透，工具按钮只保留实际热点 |
| 长按后桌宠没了 | 仅凭按键日志无法区分退出、隐藏、崩溃或失去渲染 | 联看进程、窗口、帧与输入；保留用户实测时段，修后复现同一路径 |

专项步骤见 [分层与绑定](layering-rigging.md)、[眼部与表情](eye-and-expression.md)、[动作架构](runtime-native.md) 和 [窗口与设置](windows-settings.md)；审美取舍见 [审美指南](aesthetic-guide.md)。

## 几个值得保留的具体纠错结果

- **眼部 v11**：记录了真实 Core/WebGL、两眼剪贴 ID 和气泡/按键同高的布局检查。它能证明遮罩与画面执行，不能证明两眼最终美术已获认可；之后仍有用户反馈。
- **困倦 v14**：在已有绑定上补独立低垂眼睑、短睫毛和放松嘴形，避免开心弯眼。差分记录中，选定的其他情绪脸部未变化，困倦脸部发生预期变化，受检查保护区没有新增差异。这不等于所有表情与所有时刻都完美。
- **视线与界面**：记录检查了空闲回正、移动接回以及鼠标手目标独立；菜单折叠/展开高度与气泡/按键共同的边框、色彩和装饰。跨 DPI 与实际桌面点击仍需目标环境证据。
- **鼠标行程 0.3.6**：该图稿的半行程由 X ±23/Y ±10 增至 X ±52/Y ±24 原画像素。浏览器与两个 Windows EXE 记录支持手掌/鼠标联动且键盘手未受影响；数值只适用于该构图，未做本轮物理输入复测。
- **静态版 0.3.7**：采用既有中性透明图，单次绘制，无 Core/模型加载、无连续动画循环、无全局键盘钩子。原生记录支持窗口显示、缩放、版本限制及配置恢复；没有把“收到轮廓更新”写成物理点击穿透已实测。

截至本次整理，互动版沿用模型 v11 与部分运行时 v14 补片。四区伸手、视线、弹性和部分脸部效果含运行时实现，不能描述为十多套新原生 CMO3 绑定。应用版本、模型版本和补片版本分别追踪。

## 过程里最应避免的重复劳动

先确认代码和导出真正加载了新资产，再判断改动无效；不要修了 PSD 但看旧 atlas，或更新了图却仍使用缓存入口。只读检查优先用清单、源码和 CLI；建模写入用当前能力支持的 Editor/API。窗口最小化、用户输入冲突或工具拒绝时，准确判断阻塞层，继续独立工作，不循环索取已存在的授权。

长期监听要覆盖用户实际测试时段，反馈到达后核对时间、进程与本次构建，不能拿上一轮超时空日志让用户一再重复。聚合计数足以排错，不记录原始按键文本。

版本拆分按最新范围执行。静态版不只是把动画开关默认关；独立入口、资源、原生能力和设置也要收束。用户要求直接 EXE 时给该文件入口；私有 GitHub 留档与买家领取渠道分开。见 [验收与交付](release-validation.md)。

本案例没有用构建、CI、参数快照或宣传片替代最终审美认可、物理键鼠复测、安装器执行、跨平台或游戏全面验收。售卖方案、平台认证和角色权利分别判断，不把本项目价格、门槛和账号流程写成通用技能。
