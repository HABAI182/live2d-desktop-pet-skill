# 双眼分层、视线与表情

适用于用户指出眼睛抠像、瞳色、闭眼、困倦或菜单情绪粗糙时。先查当前模型入口和运行时覆盖层；同一只眼可能同时存在于底图、原生 ArtMesh 和补片中。不要只盯着最上面一层修。

## 从现象定位到层

| 现象 | 先排查 | 修复目标 |
| --- | --- | --- |
| 移动眼珠后留下旧眼、白块或毛边 | 底图是否仍画着完整眼睛，眼层是否夹带脸/刘海 | 清理旧眼，补全眼后皮肤；保留真正眼睑描边 |
| 一边正常另一边露馅 | 两眼各自的裁片、UV、遮罩与倾斜角 | 两边独立检查，不能镜像套同一矩形 |
| 眼珠越界、随头动时遮罩滞留 | mask ID、坐标空间、运行时顶点更新 | 虹膜受本眼眼白/开口遮罩约束，二者随同一头部变形 |
| 闭眼还有一整圈眼眶 | 旧睁眼描边、眼白、高光或补片没退出 | 真正换成闭眼结构，不在睁眼上盖一根线 |
| 参数对、画面仍不困 | 把开心笑眼用于困倦，只有 Zzz 改变 | 重做眼睑走势与嘴形，降低表情紧张度 |
| 瞳色蓝过头或青过头 | 参考职责、色彩配置、全局滤镜、局部重绘 | 在指定虹膜范围校色，保护肤色和头发 |

## 可动眼睛需要完整结构

按图稿拆分皮肤底层、眼白/开口、虹膜/瞳孔/高光、睫毛/眼线及闭眼形。可以把适合共同运动的细节合层，但每个移动层只携带属于它的像素。不要平移包含大片脸、头发和旧眼框的眼睛矩形。

清除底图上被新眼覆盖的旧眼残像，补出干净的眼后皮肤；补片内部衔接原有皮肤渐变，外轮廓不任意羽化。两个眼睛的眼距、高低、倾斜和大小都以认可底稿为准，不强制对称。

虹膜通常由本眼的眼白/开口 ArtMesh 剪贴。记录实际 ID，而非假定 ArtMesh4 在别的模型中也代表虹膜。Cubism 官方说明了剪贴 ID 与半透明遮罩边缘露色的机制；mask 本身的露边应按结构处理，不能一律当抠图白边擦除。见 [Clipping Mask](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/)。

若运行时在 Core 更新后自行改变顶点，检查当前 Framework 是否仍会重绘变化的遮罩。秧秧曾需要将自定义顶点变化纳入 mask 的更新判断；这是该渲染器的适配，不是给所有 SDK 复制一次方法覆盖。先查所用版本的 [官方 Web Framework 源码](https://github.com/Live2D/CubismWebFramework)。

## 闭眼不是纵向缩成细条

1. 先做可信的闭眼画稿，补齐周围皮肤；闭眼位置随原有眼部曲面与头部倾角。
2. 完全闭合时，开放眼白、虹膜、高光和旧睁眼轮廓全部退出可见结果。真正属于闭眼睫毛/眼线的线条可以保留。
3. 半闭阶段检查上下眼睑、开口和虹膜是否连贯；不要以“开放度为 0”替代视觉检查。只有 0/1 透明度切换的绑定也不能称连续眼睑变形。
4. 按“进入 → 保持 → 自动眨眼/视线叠加 → 退出”检查。退出后恢复当前应有状态，不残留缩小眼球、单眼闭合或旧表情补片。

困倦可用低垂的上眼睑、较平或自然下落的闭眼线、放松嘴形与缓慢呼吸；开心闭眼常有更明显上扬弧度和提起的脸颊。按角色画风选择，不能把某种弧线写成通用公式。先隐藏 Zzz 看脸能否表达困意，再恢复辅助符号。

## 瞳色与视线

校色时把身份参考和当前底稿放在相同色彩处理下比较，记录参考版本。先核对色彩配置是否引起意外变化，必要时只调整虹膜的色相、明度、饱和度；不要用整幅 saturation 过滤器补偿眼睛。PSD 非 sRGB 配置可能改变导入颜色，处理方式见 [官方 PSD 注意事项](https://docs.live2d.com/en/cubism-editor-manual/precautions-for-psd-data/)。用户有意二创的颜色优先，不强行恢复所谓官方色。

两眼共用视线目标，但各自按眼白空间和透视调幅度；眼球可动范围不是一个必须相等的像素数。增大视线前先确认遮罩与皮肤补全，在左右/上下/对角极值和小尺寸检查斗鸡眼、露底与睫毛形变。

需要“鼠标停几秒后回正”时，分别保留鼠标手目标、视线目标与空闲计时。按真实移动更新时间，静止重复采样不续命；指针在视线范围外继续移动，也不能因目标已钳制到同一点而误判静止。延迟和回正开关可配置，回正平滑，重新移动及时接回；视线回正不应带着鼠标手归零。见 [runtime-native.md](runtime-native.md)。

## 菜单情绪需要有脸部语义

“开心”“脸红”“困倦”等是情绪状态，不是给按键浮显换一枚图标。先选少量质量可控的情绪，扩展时写清眼睑/眉、视线、嘴、脸颊、姿态与装饰的差异。

| 情绪方向 | 脸部与姿态线索 | 常见敷衍做法 |
| --- | --- | --- |
| 开心 | 眼睑/眉放松，嘴角与面颊共同变化 | 默认脸旁多一颗心 |
| 脸红/害羞 | 贴合脸型的柔和晕染，细微视线/嘴形变化 | 两个硬边、纯色粉红椭圆 |
| 惊讶 | 眉眼张力、口型与短暂反应一致 | 只放一个很小的感叹号 |
| 困倦 | 眼睑重量、放松口型、呼吸节奏 | 开心弯眼加 Zzz，旧眼框仍在 |
| 认真/思考 | 眉眼、视线与嘴的克制变化 | 只替换文字，脸完全一样 |

脸红的颜色、纹理与透明度融入原图，不盖住原有线稿；晕染随脸部网格走。符号可做有描边、倾斜和轻弹的 Q 版造型，尺寸要在常用桌宠大小能看清，也要避开发饰和眼睛；不以放大符号掩盖没完成的脸。

制作一张同尺度、同背景的情绪对照表，并实际看切换。每个按钮应有可辨识结果；“日常 + 16 种情绪”与“共 17 状态”等计数统一口径。动画段数、情绪数、快捷键数分别列，不拿数量充当完成度。

## 最小验收组合

只覆盖本轮变化：两眼中性与视线极值、眨眼的闭合/中间/重开、困倦/开心区分及返回日常。再组合一个最大头部弹性或手臂极值，以暴露跟随接缝。必要时使用 [视觉纠错记录](../templates/visual-review.md)。

像素差分证明保护区域是否变化；参数快照证明状态是否执行；遮罩 ID 证明引用关系。三者都不能独立证明“眼睛已经好看”，需实际画面和对应审美判断。
