# 工具选择与方法

## 先选能直接处理问题的工具

| 问题 | 首选工具/方法 | 需要知道的边界 |
| --- | --- | --- |
| 接手工程 | rg、Git、项目进度与 manifest | 搜索结果不是当前生效入口，仍需追踪引用 |
| 模型缺依赖或映射错误 | cli-anything-live2d / JSON / 校验脚本 | CLI 不会自动画出隐藏区域或绑定新网格 |
| ArtMesh、变形器、关键形 | Cubism Editor 与官方导出工具 | 必须保存并核对导出源；不要猜测修改专有二进制 |
| 角色补画、候选原画 | 图像生成/编辑工具或可编辑画稿 | 候选图仍需对齐、分层和极值验收 |
| 残边和缺角定位 | Alpha/纹理统计、参考对齐、网格/UV 检查 | 数据不能替代实际运动中的观感 |
| 参数、动作残留 | Core/offline 参数检查与小范围单元测试 | 不能证明 WebGL 外观或原生桌面行为 |
| 实际模型和设置 | 本地浏览器、Playwright、WebGL 截图 | 不证明系统托盘、全局键盘或透明原生窗 |
| 全局输入、窗口生命周期 | Rust/Tauri/Win32 API、实际 EXE | 当前 OS 的验证不自动覆盖另一个 OS |
| 编辑器自动操作 | 已授权的电脑操作 / UI Automation | 先观察窗口与文档，再操作；应用权限与文件权限不同 |
| 打包与留档 | 项目构建脚本、Tauri CLI、SHA256、Git/gh | 不覆盖旧文件；不把大依赖/缓存/私人日志推到 Git |

## 模型 CLI 的正确用途

已安装 `cli-anything-live2d` 时，先看它的 SKILL/help，优先 inspect、validate、deps、textures、physics、param-list、manifest 与 diff。

orphan 报告只是“这个入口没引用”，不等于整个工程无用。一个贴图可能被另一入口、编辑器源、修复脚本或备用模型引用。删除前搜索项目引用并保存备份。

JSON 中的 motion/expression 引用、淡入淡出或参数预设可以使用 CLI 编辑，检查其自动备份。新网格、原画结构与正式绑定仍由编辑器/受支持工具完成。

## Core 与自定义渲染

不要自行拼一个假的 moc3。加载真正的官方 Core，验证当前文件兼容性，并保留供应商许可。

自定义绘制要考虑纹理坐标方向、透明混合、剪裁、绘制顺序、资源释放和 resize。运行时补片与变形器都要跟随原生模型的实际坐标。

常用做法：静态拓扑预计算，动态位置随帧更新；用共享驱动值关联鼠标与手；修正局部排序时保留其余顺序；用表达式解析后的资产 ID 判断是否切换，避免相同资产反复淡入。

## 自动化效率

优先结构化读取与命令，避免一页页点击查信息。对原生编辑器的动作，保存当前文档、确认窗口标题与焦点、再进行短的可观察步骤。一次只做一类关键修改，马上保存。

若 Java 承载 Cubism，工具可能将它识别为 java 而不是 Cubism。文字同意不保证工具已放行；文件“完全访问”也不证明某应用可以被电脑操作。解释实际报错，然后继续不依赖该工具的工作。

本机没有相关 MCP 时明确说没有。不要把能改 model3 JSON 的服务宣传成能自动完成 Cubism 美术绑定的 MCP，也不要用未核验的 GitHub 项目执行不透明脚本。

## 文件和磁盘

查看大目录、缓存、依赖和交付文件大小；保留源模型、当前/上一版本和版本清单。缓存可再生成不等于所有 build 目录都可删，有的工程把唯一导出文件放在那里。

Windows 上删除/移动前计算绝对路径，验证它仍在预期目录里；使用同一 PowerShell 的 LiteralPath 操作。不能枚举路径后拼接到另一个 shell 里删除。

不要在日志里打印令牌、cookie、环境机密或原始键盘内容。GitHub 授权令牌由 gh/连接器管理，不写入仓库配置、skill 或脚本。
