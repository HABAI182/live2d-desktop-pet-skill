# 原生窗口、启动和设置

## 桌宠与交互窗口分工

桌宠常驻、不因输入动作抢焦点；设置与互动菜单在用户打开时可以置顶并聚焦。设置关闭后，清理独立窗口的过滤状态。输入层必须区分“正在自己的编辑窗口输入”与“桌宠本体恰是前台”。

菜单优先放在可见主体旁边，按当前显示器工作区选择左右或上下空位。独立窗口能减少遮挡，但仍要处理焦点和拖动生命周期：

- 新的外部按下可关闭菜单，不能只监听菜单网页内部的 click。
- 拖动开始后不能因 blur、鼠标移出或窗口移动立刻消失；先识别拖动状态，再处理收起。
- 右键、Esc、关闭按钮和选择动作各自有一致行为；拖动结束后的外部点击仍可关闭。
- 检查原生标题栏/自绘拖动区与普通按钮是否冲突，不把按钮当拖动面板。

浏览器中 div 拖动顺畅，不证明原生窗口的失焦与全局外点处理正确。

菜单高度由实际内容决定。字体就绪、情绪区展开、字号或版本功能变化后重新测量，再合并更新原生高度并限制在工作区；不要用固定高窗口承载很少的内容。放大字体时保留必要滚动，不能为消除留白把真正内容裁掉。

## 透明与可点击是两套状态

透明窗口仍可能按整个矩形命中。局部透明穿透需由当前可见轮廓驱动，保留头发环内部孔洞、侧边空白、键盘下方留白；底部工具只增加按钮实际热点，不把整条底栏填成不可穿透区域。

一种已在秧秧工程采用的做法是：渲染后下采样 Alpha → 行程压缩或其他紧凑轮廓 → 原生层命中判断。采样变换必须与 canvas 的 object-fit、object-position、CSS 缩放和 DPI 一致，动态补片也要纳入；装饰性气泡是否接收点击按产品行为定义。阈值与少量边缘容差需在细发丝、按钮和孔洞间折中，不统一扩大成大矩形。

浏览器 pointer 事件在窗口穿透后可能收不到，恢复命中不能只依赖网页的 pointerenter。原生层需独立获得指针位置并更新穿透状态。按下时固定本次点击归属直到释放，避免指针跨过角色时偷走其他软件的拖动；拖动桌宠时则保持其捕获。检查全窗穿透、手动隐藏与局部轮廓策略的优先级。

保留托盘或用户可发现的找回快捷键。测试外部背景上的透明孔、底部空白、实体角色、工具按钮、穿入/穿出及拖动；轮廓 IPC 已更新只证明数据到达，不代表真实点击通过了原生窗口。没有目标 OS 实测就明示待验收。

## 冷启动不先展示静止贴图

输入监听初始化、前端订阅、Core/模型加载和窗口显示是独立阶段。加载时可隐藏窗口，真实 renderer ready 后再显示，避免先露出一秒完全静止的样张；加载失败应有可恢复的明确状态，不永久隐身。

首次启动不要先点击桌面：直接测试键鼠、空闲眨眼，再打开设置。热更新、已聚焦的预览页和已经运行过的实例都不是冷启动证据。

聚合计数能区分输入停止与渲染停止。不要把所有故障都归因后台节流；先测帧数与心跳。

“按住键以后桌宠关了”先检查进程是否退出、窗口是否隐藏/最小化、全窗穿透/淡化、崩溃与 renderer 心跳，再查输入。不能以一条 hook 计数证明桌宠可见；也不能立即把快捷键、键盘驱动或用户操作当成原因。

## WebView2 的实际边界

管理员宿主可能忽略环境变量设置的浏览器参数，代码传入参数的行为不同。同一共享 profile 下的主体/设置/菜单应保持兼容配置。

浏览器 flags 是诊断手段，不是默认生产契约。Microsoft 明确提醒其可能变化，见 [官方说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags)。优先使用受支持的宿主生命周期/调度接口；确需兼容策略时记录适用范围和移除条件，不批量复制“禁用一切限制”参数。

CDP 调试端口仅在显式本地诊断入口开启，结束后恢复普通启动并确认端口关闭。不要为了测试放宽日常 IPC 白名单、关闭 Web 安全或对外暴露调试接口。

## 拖动、磁吸和多屏

布局同时记录逻辑像素、物理像素、显示缩放和工作区。窗口范围包含透明留白时，贴底与磁吸应按角色可见边界计算，否则拖到屏幕底部还会悬空。

把拖动键放在主体右下可点的位置，尺寸小于视觉主角。装饰沿用角色色块与饰件语言；六点把手并非必须，可少量点阵居中。键盘、鼠标线和配角是否存在由当前图稿决定。

全屏避让按桌宠所在屏幕判断；手动隐藏保持权威。测试底部拖拽、相邻显示器、不同 DPI 和无边框游戏时分别记录，不把主屏测试扩展成全环境保证。

## 连续缩放与覆盖层

主体、按键提示、气泡、拖动热点和原生窗口尺寸共用尺度。只改 CSS transform 会留下裁切、空白与点击位置错误。覆盖层应有足够的最小可读尺寸。

滑条采用 draft预览→合并原生写入→释放时 flush/保存；用 revision 防止旧结果覆盖新值，失败时回滚并提示。字号、动作速度与幅度也应有数值和键盘操作。

长离示例为大小50%–200%、设置字85%–130%、手速50%–200%，这些是产品设置，不是所有桌宠必须采用的参数。

## 设置与默认值

开关说明用户看见的结果，按外观/互动/桌面/高级或现有合适分类组织。保持字阶、对齐、间距与控件尺寸；不把实现细节和诊断名称塞进普通用户流程。

新增默认值只补旧数据中缺失字段，不覆盖已有显式选择。对长离当前案例：按键浮显开、上限1（可调1–6）、长按重复关、靠近淡化关、全屏避让关；用户授权的高权限启动开。迁移其它项目时依据其用户选择，不能照抄。

自动化改变真实用户设置时，在 `try/finally` 恢复原偏好；若测试中断过，应先核对基线。用户明确提出新默认或新偏好后以新要求为准，而非恢复测试误关的旧状态。最终检查持久化、窗口当前值与真实提示是否可见。
