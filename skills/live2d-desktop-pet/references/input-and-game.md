# 输入状态、长按与游戏兼容

## 用物理状态驱动连续动作

至少区分 `down / repeat / up`，事件带临时物理键标识、所属区和深度，不带输入文本。手部仅保留当前按住集合，松开即移除；不追加为历史或发送到网络。

| 事件 | 手 | 头部/完整动作 | 按键浮显 |
| --- | --- | --- | --- |
| 新的物理 down | 更新落点，开始按压 | 允许一次弹动/新的动作起点 | 显示一个短期提示 |
| 同一键 autorepeat | 保持按压和所有权 | 不重启弹簧、按压周期和 motion | 按独立重复开关决定，默认策略由项目指定 |
| up | 删除该键；同手还有键就保持其落点，否则回位 | 不当作一次新敲击 | 不重新浮现 |

同一只手按住 W 和 Space，松开 Space 后应继续维持 W，不应整体松手。重复事件也不能让已经按住的旧键反复抢回新键的落点；选择“最新仍按住键”等明确策略。

浏览器预览也要有 keyup，失焦时释放其本地按住集合；原生版本在自己的设置获得焦点后，即使抑制新输入，仍应处理此前按键的释放。考虑队列丢包、设备断开或睡眠恢复时的状态复位，避免永久按住。

不要只修按键提示。长按抖动可能同时来自 presentation 的 pressedAt、头部 spring kick、旧 authored motion 的重启动作，以及前端状态机的重复计数。

## 画面镜像与所有权

物理区→角色手→画面网格→导出参数分开映射。需求可以从单手覆盖全键盘改成两手分区，这是真实需求变更，不是“旧实现永远正确”。记录切换版本，见 [keyboard-space.md](keyboard-space.md)。

鼠标位置、鼠标手、必要的线缆共用位移源；按压独立。双手键盘中，右手仍有键按住或尚在回位时，鼠标不能抢回控制。若用户选择无线鼠标，不生成线缆。

## Windows：先分清输入没来，还是画面不动

保留本次进程中的聚合计数：原生接收、语义发出、前端接收、模型绘制、心跳年龄。只用于诊断，不存储逐键内容和前台应用历史。

| 现象 | 先查 |
| --- | --- |
| 眨眼也停止 | 帧调度、WebView 生命周期、遮挡/后台策略、异常或设备丢失 |
| 眨眼继续，手不动 | 输入计数、过滤条件、窗口焦点、权限及手部映射 |
| 原生有事件，前端没有 | 事件桥、监听注册时机、窗口标签与订阅生命周期 |
| 前端收到，模型手不动 | 参数映射、冲突 motion、手部所有权与实际渲染值 |
| 游戏菜单能用，控制角色时失效 | 测试阶段差异、游戏输入方式、权限完整性，而非笼统“全屏” |

Raw Input 注册成功只证明注册，不证明游戏中仍有包。可按实际需要组合 Raw Input 与独立当前状态观察，并做每键去重；不无条件安装所有 hook 或向游戏注入代码。

`GetAsyncKeyState` 的高位表示当前按下，低位“最近按过”不可靠；零也可能表示访问受限。鼠标左右交换另按系统逻辑映射处理。参考 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate)。

两条观察通道必须一起验证 raw先到/poll先到、长按、快速松开再按和仅一条通道有事件。去重标志在释放时清理，不能吞掉真正的新按下。

## 权限是排查结果，不是万能默认

观察当前进程与游戏的完整性级别，记录是否存在更高权限前台进程，而非仅凭用户对启动器的猜测。确认权限差异后，可在已授权范围内提供标准 UAC 管理员重启；取消时保留普通进程，避免启动循环。

长离 0.7.15 经普通候选失败、管理员候选在鸣潮实际角色控制中成功后，用户明确选择默认高权限启动。**这是该项目的偏好，不要求所有桌宠默认管理员。** 不修改安全策略、不关闭反作弊、不绕过系统确认，也不宣称对所有游戏都有效。

文件访问、网络代理、电脑操作应用白名单与 Windows 完整性是不同层。已经同意 SDK 下载或 Java 窗口操作，不等于实际工具已放行；不要不断要求重复文字授权。

## macOS：另一条原生输入链路

使用目标系统支持的输入监听与授权接口。输入监控授权与 Windows 管理员模式无关。更新 APP 后若失效，检查系统中安装的应用身份和输入监控条目，必要时重新添加已安装应用并重启。

验证真正控制角色/外部程序时的键鼠，不只在应用菜单或登录界面敲键。Mac 上的权限/签名/应用路径问题由 Mac 实机确认；Windows 上读到 ARM64 不能替代这一步。

## 最小验收场景

鼠标单独、键盘单独、快速跨区、鼠标→键盘、长按3秒再松开、同手多键、Space、多键提示上限与重复开关。游戏修复需要在真实玩法阶段核验，记录测试者与精确构建。

恢复测试改过的设置并检查最终生效状态。若用户发现按键提示消失，先读开关和持久化结果，不默认是功能被删或重新安装才可解决。
