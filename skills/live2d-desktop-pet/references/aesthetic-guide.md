# 怎样判断桌宠的审美质量

好看不是堆特效。桌宠要在常驻、缩小、快速输入和安静待机时都舒服。

## 四个层次

1. **辨识度**：缩小到常用尺寸还能认出角色。发束、眼睛、饰品和颜色的关系正确，而不只是一种发色。
2. **结构**：脸、手、键鼠和服装有连续形体。没有缺角、残边、穿插或明显补丁。
3. **动态**：输入有直接回应、回弹有节奏、次级动作有因果，停止输入后能够安静下来。
4. **界面秩序**：设置、气泡与菜单清楚、规整、可读，给角色留空间。

层次 1/2 未稳时，大幅动态只会放大问题。

## 角色美术

- 以参考图为基准确定头身比例、脸颊轮廓、眼距、眼睛纹样和饰品位置。不要给所有 Q 版角色套同一个圆脸/大眼模板。
- 控制发束数量与外轮廓；新画的发束如果改变辨识度，需要重新对照原图。
- 描边厚度与颜色统一，皮肤保留源图温度和渐变；补画与原画的光线方向一致。
- 键盘和鼠标遵循同一透视。Space、键列、前后排要能解释手部落点。
- 轮廓在浅/深背景都没有白边、黑边、半透明脏像素。别用纯白背景掩盖抠图问题。
- 角色无需完全对称：倾斜的脸与两眼有自然高度差。判断失衡应以参考与整体结构为依据。

## 动作：软弹但不乱晃

把一次反馈拆成“输入 → 压下 → 释放 → 回弹 → 次级余韵”。按下短而清楚，释放轻微过冲，最终衰减；头发和挂饰略迟于主头部。

以下只是起调范围，必须看真实模型调：

| 通道 | 常规起调 | 活泼档方向 |
| --- | --- | --- |
| 按压响应 | 60–100 ms 压下，220–400 ms 回弹 | 更短响应，略增加过冲，避免抖动 |
| 主体弹跳 | 头高约2–5%位移 | 可尝试5–9%，先保证边缘不破 |
| 头部挤压 | 约3–8%形变 | 可尝试8–12%，保留脸与饰品结构 |
| 次级滞后 | 约60–140 ms | 差异化延迟，不能所有配件同相位 |
| 眨眼 | 90–130 ms 闭合、35–70 ms 停留、130–200 ms 睁开 | 动作频率与表情联动，不用生硬跳帧 |

每帧都在动不等于灵动。待机时以呼吸、小幅视线与偶尔微动作保持存在感；快速敲键时才提高主动作强度。鼠标滑动、按压和键盘输入不要都套同一“整个人摇一下”。

配角按身份与画稿设计动作：长离的小凤凰可有翅膀、尾羽和火苗；秧秧的玄翎雀可有身体轻蹦、翅尖与尾羽余韵。根部有依托，动时不掀开底层缺口，也不整块来回翻摆。次级动作的频率与对比度低于主角；图稿没有的配角不默认补上。

## 表情语义

用户看得出“开心”“害羞”“困倦”“生气”的区别吗？按钮名称不能代替完成度。

开心首先检查眼睛与嘴的配合；困倦检查眼睑重量、放松嘴形与呼吸，不能把开心弯眼直接改名；害羞有细微视线与融入皮肤的晕染；生气先有眉眼张力，再考虑符合角色的特效。特效是辅助，具体拆层与验收见 [眼部与表情](eye-and-expression.md)。

“像某作者一样好”需翻译成可判断的目标：小尺寸能认出情绪、同一输入有干净回弹、双眼闭合完整、手与设备接触可信。借鉴完成度和节奏，不承诺复刻参考作者资产或用未经证实的比较夸大成果。

## 设置：借鉴 iOS / Win11 的秩序

- 使用统一的字阶、行高、圆角和间距。先做栅格与对齐，再做阴影。
- 一种强调色，温和中性色；不用同时混用玻璃、霓虹、渐变和重阴影。
- 类似项目组成一组，主要标签对齐，控件位于一致的尾端。描述只说明真正需要解释的设置。
- 推荐简单的外观、互动、桌面、高级分类；具体分类仍以现有项目为准。
- 开关状态清楚，滑条有可读数值与合理范围，键盘也能操作；字号与对比度满足常用桌面距离。
- 菜单尽量在角色旁边，设置打开时高显示优先级；拖拽把手小而可点，不占据主体审美焦点。
- 气泡与按键浮现随主体尺度变化，但在极小尺寸要有最低可读约束；气泡内容简短、自然、不每次重复。

气泡与按键用同一套边框、字阶、圆角、阴影和点缀语言，再给各自合理的宽度与字号。秧秧案例可从羽毛、金花、红绳、蓝黑与金色提取少量元素，不把完整复杂饰物复制到每个边角。边框加粗或放大按键时同时看小尺寸与长标签，防止挤压文字。

位置按用户最新更正执行：本例调整的是文字泡下移至键提示附近并略左，键提示原高度保留。换项目按脸、饰品、配角和屏幕边缘重新排布，不固定套坐标。

菜单紧凑要同时改变内容布局与原生窗高度；不能只删除底部 DOM，仍留下高大的空白窗口。表情展开/收起、字体加载、字号和版本功能差异都可能改变内容高度。

## 图标

图标以角色的可辨识面部或核心元素为主。避免把完整复杂场景硬塞到 32px 图标里；缩小检查轮廓、色块和表情。

圆角与几何秩序应体现在外形、留白和元素关系，不必重画成泛用的几何人物。用户要求原图作图标时，保留其身份，使用合适裁切与边距，不换成抽象房子或不相关标识。

## 快速审美验收

看中性、移动极值、常用小尺寸和安静待机四种状态。问：角色认得出吗、结构完整吗、输入反应清楚吗、动作能收住吗、UI 有序吗？先修明显违和，再处理不影响日常的小细节。

不要用“风格参考某作者”代替判断；应能具体指出弹性时序、表情清晰度、画面层级和干净轮廓如何改善。

## 把“不满意”变成修复优先级

| 优先级 | 失败判据 | 看什么 |
| --- | --- | --- |
| 先修结构 | 比例/颜色漂移、白边、缺角、手夹带脸发、闭眼残框 | 同基准叠图、反差背景、两眼与两手独立裁片、极值 |
| 再修语义 | 开心/困倦分不清，脸红只靠硬椭圆，所有动作同一整图晃动 | 去掉辅助符号的脸、情绪对照、主次运动 |
| 再调体验 | 视线盯死、按压拖沓、回弹收不住、鼠标手幅度不足 | 实时移动/静止、短按/长按/快速输入与停下 |
| 最后润色 | 字小、边框不统一、符号看不清、菜单留白过大 | 常用大小、长标签、字体变化、真实原生窗口 |

顺序用于避免掩盖缺陷，不是禁止同步做独立的程序工作。像素差分与数值范围是定位证据，美感仍需可解释的画面判断；人工认可未取得时如实记录，继续可做的修复。按需使用 [视觉纠错记录](../templates/visual-review.md)。
